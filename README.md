# 工作日志移动端（zl-worklog.html）

公司 CMS（zl-cms）的 PC Web 端没有适配手机，用手机浏览器打开时表格挤、按钮小、几乎没法填。这个项目把「工作日志」模块单独抽出来，做成一个**离线单文件 HTML**，直接调用 PC 端同一套后端接口，在手机上完成登录、查看日志、写日志、提交部门日志。

- 交付物：`zl-worklog.html`（单文件，内联 CSS/JS，无外部依赖，双击即可打开）
- 设计取向：375px 窄屏起步，≥768px 扩屏；正文 ≥14px、输入框 ≥16px，所有可点区域满足手指点击尺寸

## 功能

| 模块 | 说明 |
| --- | --- |
| 登录 | 账号/手机号 + 密码（≥6 位）。登录成功后在本地保存凭证，下次打开免登录 |
| 我的日志 | 按日期读取自己的日志并回填表单；可修改后重新提交（同一接口幂等覆盖） |
| 写日志 | 四种工作状态、可增删时间段、自动累计工时、工作内容必填 |
| 部门日志 | 按日期 + 部门浏览全部门当日日志，显示人数、工时、时间段，自己那条带「我」标记 |
| 提交部门日志 | 对当前「查看部门」提交当日部门日志，已提交则显示状态、不再给按钮 |

## 使用方式

1. 把 `zl-worklog.html` 传到手机（微信/文件传输/数据线均可），用浏览器打开；
2. 首次登录后即可免登录使用，建议「添加到主屏幕」当作轻应用；
3. 断网时页面展示本机缓存的日志数据，并明确提示「可能不是最新」；提交类操作仍需联网。

**前提：后端允许跨域。** 该 API 的 `OPTIONS` 预检实测返回 `204` 且带 `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Headers: authorization,content-type`，因此 `file://` 直接打开也能调通。如果后端后续收紧 CORS，页面会停在「网络连接失败」，需同步调整白名单（放行 `Origin: null`）。

## 接口契约

本页所有请求路径、参数、请求体字段与返回值含义，均与 PC 端一致，**不做二次定义**。

契约一律以 `reference/` 下的两个 PC 端源文件为准，现场检索获取即可；本文档不复述字段清单，避免接口调整后文档变成过期副本：

- `reference/bundle.js`：搜 `"/Worklog/` 可一次列出全部日志接口（`reference/worklog_component.js` 里没有任何接口路径，不要在那里找）；搜 `baseURL` 取基址与 axios 配置；**不要**用 `sft(` / `lft(` 这类压缩后的函数名当锚点，它们每次构建都会变。
- `reference/worklog_component.js`：未压缩、可读，用来核对字段名与表单规则（工时、状态、时间段、部门提交标记），不含路径。

判断本页实际在调哪些接口，直接看 `zl-worklog.html` 里的 `api('get' | 'post', …)` 调用点，这是唯一权威来源。

## 业务规则

- 工作状态：正常上班、全天请假、上午请假、下午请假四种，切换时自动调整时间段与文案；
- 时间段必须是 **5 分钟倍数**，开始早于结束，且互不交叉重复；
- 工时由时间段自动累加（保留 1 位小数），不手工填写；
- 正常上班且工时为 0 时，弹二次确认（红色「仍要提交」），避免误提交空工时；
- 请假类状态会自动带出默认时间段与文案，切回「正常上班」时恢复默认时段。

## 登录态与有效期

- 本地存储键：`lw_h5_auth_v1`（凭证）、`lw_h5_last_seen_v1`（最后使用时间）；
- token 的真实有效期**由服务端决定**，客户端拿不到（登录响应不含任何时效字段，PC 端也不记录）。页面按 PC 端同一判定处理身份失效信号；
- 失效与无权限分开处理：身份失效 → 清除凭证、回登录页；无权限 → 只提示，不动登录态；
- 额外兜底：**连续 3 天未使用即作废**。启动时或任一请求前判定，超期直接清除凭证并提示重新登录；每次使用会刷新时间戳（5 分钟内最多写一次，减少存储写入）；
- 手动「退出登录」会一并清除凭证与时间戳。

## 离线缓存

- 缓存键前缀 `lw_h5_cache_`，按「日期 + 部门」缓存日志数据；
- 读取失败时回落到缓存并显著提示；「我的日志」未成功读取时**禁用提交按钮**，避免把已存在的当天日志覆盖成空表单。

## 已知限制

- **未实现**：撤销部门日志、部门日志截图预览/下载/复制到剪贴板（PC 用 `html2canvas`）、按姓名筛选；
- 登录接口的 4 位图形验证码字段在 PC 端也只做前端展示、不随请求发送，本页同样未做；
- 新增时间段与现有时间段冲突时只提示、不阻塞（与 PC 端行为保持一致）；
- 页面不发起任何后台轮询，数据仅在进入页面、切换日期/部门、提交后刷新。

## 维护提示

- 单文件自包含：CSS 在 `<style>`、JS 在 `<script>`，不拆 js/css 文件；改动后直接覆盖原文件即可；
- 改接口前先回到 `reference/bundle.js` 核对（搜 `"/Worklog/` 与 `baseURL`），字段名再到 `reference/worklog_component.js` 交叉印证，不要照本文档硬拼；
- 回归验证方式：先 `node --check` 校验脚本语法，再用无头浏览器渲染关键状态（登录校验提示、已加载可提交、未加载禁用、零工时确认、部门日志三态）比对截图；
- 修订前把当前版本复制进 `_backup/`（不存在就先建目录），保留可回退的上一版。

## 安全提示

- 凭证存在 localStorage，`file://` 页面共享同一存储域，本机任意本地 HTML 均可读取。页面已用「3 天闲置自动清除 + 服务端 `-2` 双判定」压缩暴露窗口；如对安全要求更高，可改为 `sessionStorage`（代价是每次打开都要重新登录）；
- 本页只读取与提交工作日志，不涉及其他 CMS 模块；请勿把带真实 token 的浏览器数据导出分享。
