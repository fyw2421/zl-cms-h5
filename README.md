# 工作日志移动端（zl-worklog.html）

公司 CMS（zl-cms）的 PC Web 端没有适配手机，用手机浏览器打开时表格挤、按钮小、几乎没法填。这个项目把「工作日志」模块单独抽出来，做成一个**自包含单文件 HTML**，直接调用 PC 端同一套后端接口，在手机上完成登录、查看日志、写日志、提交部门日志。

**它不是纯离线应用**：单文件可以离线拷到手机直接打开（`file://`），也可以由 GitHub Pages 发布成网址在线访问，两条路都真实请求后端接口。区别只在于页面从哪里加载，以及登录态存在哪个域名下。

- 交付物：`zl-worklog.html`（单文件，内联 CSS/JS，无外部依赖，双击即可打开）
- 设计取向：375px 窄屏起步，≥768px 扩屏；正文 ≥14px、输入框 ≥16px，所有可点区域满足手指点击尺寸

## 功能

| 模块 | 说明 |
| --- | --- |
| 登录 | 账号/手机号 + 密码（≥6 位）。登录成功后在本地保存凭证，下次打开免登录 |
| 我的日志 | 按日期读取自己的日志并回填表单；可修改后重新提交（同一接口幂等覆盖） |
| 写日志 | 四种工作状态、可增删时间段、自动累计工时、工作内容必填 |
| 部门日志 | 按日期 + 部门浏览全部门当日日志，显示人数、工时、时间段，自己那条带「我」标记 |
| 提交部门日志 | 对当前「查看部门」提交当日部门日志，已提交则显示状态、不再给按钮 |

## 运行方式

### 方式一：在线（GitHub Pages，日常推荐）

1. 手机浏览器直接打开 `https://fyw2421.github.io/zl-cms-h5/`，建议「添加到主屏幕」当作轻应用；
2. 首次登录后免登录（凭证存在该域名的 localStorage，连续 3 天未使用即作废，需重新登录）；
3. 页面本身是公网可访问的，但读日志、写日志、提交部门日志都要登录，鉴权在服务端。

部署细节、启用条件见下方「发布与部署」。

### 方式二：离线（本地文件）

1. 把 `zl-worklog.html` 传到手机（微信/文件传输/数据线均可），用浏览器打开 `file://` 地址；
2. 登录态与 Pages 域名**不共享**，两种方式各自登录一次，互不迁移；
3. 页面加载不依赖任何外部资源，断网也能打开界面，但登录与提交必须联网。

**前提：后端允许跨域。** 该 API 的 `OPTIONS` 预检实测返回 `204` 且带 `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Headers: authorization,content-type`，因此 `file://`（`Origin: null`）与 Pages 域名（`https://fyw2421.github.io`）都能直连。如果后端后续收紧 CORS，页面会停在「网络连接失败」，需同步调整白名单。

## 发布与部署（GitHub Pages）

- 部署方式：**GitHub Actions**（`.github/workflows/pages.yml`），只在 `push main` 或手动触发时运行；
- 产物：workflow 只把 `zl-worklog.html` 复制成 `_site/index.html` 上传，`reference/`、`scripts/`、文档都不会被发布；
- 访问地址：`https://fyw2421.github.io/zl-cms-h5/`（根路径即页面，无需带文件名）；
- 前提：仓库 Settings → Pages → **Source 必须选 `GitHub Actions`**（不是 Deploy from a branch），否则部署步骤会因「Pages 站点未启用」失败。

## 接口契约

本页所有请求路径、参数、请求体字段与返回值含义，均与 PC 端一致，**不做二次定义**。

契约一律以 `reference/` 下的两个 PC 端源文件为准，现场检索获取即可；本文档不复述字段清单，避免接口调整后文档变成过期副本：

- `reference/bundle.js`：搜 `"/Worklog/` 可一次列出全部日志接口（`reference/worklog_component.js` 里没有任何接口路径，不要在那里找）；搜 `baseURL` 取基址与 axios 配置；**不要**用 `sft(` / `lft(` 这类压缩后的函数名当锚点，它们每次构建都会变。
- `reference/worklog_component.js`：未压缩、可读，用来核对字段名与表单规则（工时、状态、时间段、部门提交标记），不含路径。

判断本页实际在调哪些接口，直接看 `zl-worklog.html` 里的 `api('get' | 'post', …)` 调用点，这是唯一权威来源。

## 业务规则

- 工作状态：正常上班、全天请假、上午请假、下午请假四种，切换时自动调整时间段与文案；
- 时间段必须是 **5 分钟倍数**，开始早于结束，且互不交叉重复；
- 工时由时间段自动累加（保留 1 位小数），不手工填写；
- 正常上班且工时为 0 时，弹二次确认（红色「仍要提交」），避免误提交空工时；
- **服务端规则（已实测）**：状态为「正常上班」时，工作日提交的工时不得少于 7 小时（服务端按时间段重算，不信客户端传的 `workHours`；6.9 小时被拒、7 小时整通过），否则返回 `正常工作日您选择的时间段小于7小时`；同样的时间段把状态改为请假类即可通过；
- **服务端规则（已实测）**：当天日志的结束时间不能晚于当前时间，否则返回 `工作时间段结束时间 ... 不能超过当前时间 ...`；页面对此在提交前校验；
- 请假类状态会自动带出默认时间段与文案，切回「正常上班」时恢复默认时段。

## 登录态与有效期

- 本地存储键：`lw_h5_auth_v1`（凭证）、`lw_h5_last_seen_v1`（最后使用时间）；
- token 的真实有效期**由服务端决定**，客户端拿不到（登录响应不含任何时效字段，PC 端也不记录）。页面按 PC 端同一判定处理身份失效信号；
- 失效与无权限分开处理：身份失效 → 清除凭证、回登录页；无权限 → 只提示，不动登录态；
- 额外兜底：**连续 3 天未使用即作废**。启动时或任一请求前判定，超期直接清除凭证并提示重新登录；每次使用会刷新时间戳（5 分钟内最多写一次，减少存储写入）；
- 手动「退出登录」会一并清除凭证与时间戳。

## 缓存与断网

页面不是离线应用，缓存只覆盖**读取侧**，写日志/提交始终需要联网：

- 缓存键前缀 `lw_h5_cache_`，按「日期 + 部门」缓存日志数据，存于当前页面的 localStorage；
- 请求失败时回落到缓存并显著提示「可能不是最新」；「我的日志」未成功读取时**禁用提交按钮**，避免把已存在的当天日志覆盖成空表单；
- 离线文件与 Pages 是两套存储域，缓存不互通。

## 已知限制

- **未实现**：撤销部门日志、部门日志截图预览/下载/复制到剪贴板（PC 用 `html2canvas`）、按姓名筛选；
- 登录接口的 4 位图形验证码字段在 PC 端也只做前端展示、不随请求发送，本页同样未做；
- 新增时间段与现有时间段冲突时只提示、不阻塞（与 PC 端行为保持一致）；
- 页面不发起任何后台轮询，数据仅在进入页面、切换日期/部门、提交后刷新。

## 维护提示

- 单文件自包含：CSS 在 `<style>`、JS 在 `<script>`，不拆 js/css 文件；改动后直接覆盖原文件即可；
- 改接口前先回到 `reference/bundle.js` 核对（搜 `"/Worklog/` 与 `baseURL`），字段名再到 `reference/worklog_component.js` 交叉印证，不要照本文档硬拼；
- 回归验证方式：先 `node --check` 校验脚本语法，再用无头浏览器渲染关键状态（登录校验提示、已加载可提交、未加载禁用、零工时确认、部门日志三态）比对截图；
- 修订前把当前版本复制进 `_backup/`（不存在就先建目录），保留可回退的上一版。

## 安全提示

- 凭证存在页面自己的 localStorage：离线打开时是 `file://` 存储域（本机任意本地 HTML 都能读），在线访问时是 `fyw2421.github.io` 域，两者互不影响。页面已用「3 天闲置自动清除 + 服务端 `-2` 双判定」压缩暴露窗口；如对安全要求更高，可改为 `sessionStorage`（代价是每次打开都要重新登录）；
- 本页只读取与提交工作日志，不涉及其他 CMS 模块；请勿把带真实 token 的浏览器数据导出分享；
- 走 GitHub Pages 时页面本身公网可访问，但**没有任何人能在未登录的情况下读写数据**——接口鉴权在服务端。真正需要留意的暴露是接口地址公开，以及仓库若为 public，源码同样公开。
