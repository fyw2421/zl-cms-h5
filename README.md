# 工作日志移动端（zl-worklog.html）

公司 CMS（zl-cms）的 PC Web 端没有适配手机，用手机浏览器打开时表格挤、按钮小、几乎没法填。这个项目把「工作日志」模块单独抽出来，做成一个**自包含单文件 HTML**，直接调用 PC 端同一套后端接口，在手机上完成登录、查看日志、写日志、提交部门日志。

**它不是纯离线应用**：单文件可以离线拷到手机直接打开（`file://`）、可以由 GitHub Pages 发布成网址在线访问、也可以在开发期用 PC 起的本地服务让同局域网手机访问，三条路都真实请求后端接口。区别只在于页面从哪里加载，以及登录态存在哪个域名下。

- 交付物：`zl-worklog.html`（单文件，内联 CSS/JS，无外部依赖，双击即可打开）
- 设计取向：375px 窄屏起步，≥768px 扩屏；正文 ≥14px、输入框 ≥16px，所有可点区域满足手指点击尺寸

## 功能

| 模块 | 说明 |
| --- | --- |
| 登录 | 账号/手机号 + 密码（≥6 位）；输入框回车即可提交，右上角 ? 查看说明。登录成功后在本地保存凭证，下次打开免登录 |
| 我的日志 | 按日期读取自己的日志并回填表单；可修改后重新提交（同一接口幂等覆盖） |
| 写日志 | 四种工作状态、可增删时间段、自动累计工时、工作内容必填；表单下方状态胶囊一行两段实时显示「今日日志尚未提交 / 有未提交的草稿 / 改动未保存，提交后才会更新线上 ｜ 部门日志已提交 / 部门日志未提交」，按钮文案随之在「提交日志」「更新日志」间切换；部门是否已提交取自同一次 `GetWorklogs` 返回行上的 `isDeptSubmit`（任一行 =1 即已提交），不额外发请求 |
| 草稿自动保存 | 未提交内容自动存本机，刷新、切后台不丢；当天**没有**线上记录时刷新自动恢复；**已有线上记录时刷新回到线上内容**，未提交的改动挂成表单顶部的提示条，可「取回草稿」或「丢弃」；按「用户 + 日期 + 提交部门」隔离，换账号不串 |
| 部门日志 | 按日期 + 部门浏览全部门当日日志，显示人数、工时、时间段，自己那条带「我」标记 |
| 提交部门日志 | 对当前「查看部门」提交当日部门日志，已提交则显示「部门日志已提交」并只保留「预览截图」入口 |
| 部门已提交后的只读态 | 提交部门当日已提交部门日志时，「我的日志」整块表单转只读：工作状态不能切换、工作内容不能输入、时间段只显示不能改、不能新增/删除；点任一处都提示「部门日志已提交，本日日志已锁定，不能再修改」 |

## 运行方式

### 方式一：在线（GitHub Pages，日常推荐）

1. 手机浏览器直接打开 `https://fyw2421.github.io/zl-cms-h5/`，建议「添加到主屏幕」当作轻应用；
2. 首次登录后免登录（凭证存在该域名的 localStorage，连续 3 天未使用即作废，需重新登录）；
3. 页面本身是公网可访问的，但读日志、写日志、提交部门日志都要登录，鉴权在服务端。

部署细节、启用条件见下方「发布与部署」。

### 方式二：离线（本地文件）

1. 把 `zl-worklog.html` 传到手机（微信/文件传输/数据线均可），用浏览器打开 `file://` 地址；
2. 登录态与 Pages 域名**不共享**，两种方式各自登录一次，互不迁移；
3. 页面加载不依赖任何外部资源，断网也能打开界面，但登录与提交必须联网。

### 方式三：局域网（本地开发调试，改完即刷）

开发期反复改样式时，比每次传文件到手机用 `file://` 打开高效：PC 上起一个静态服务，手机连**同一 WiFi** 直接访问，改完 HTML 后**手机刷新即可**看到效果。

在 PC 的 PowerShell 或 CMD 中执行（需已安装 Python，命令即 `python`）：

```powershell
cd C:\Users\ShenLan-Wai\Desktop\tmp\zl-cms-h5
python -m http.server 8000 --bind 0.0.0.0
```

看到 `Serving HTTP on 0.0.0.0 port 8000` 即启动成功。手机浏览器打开（IP 以本机实际联网网卡为准，下面是本机实测值）：

```
http://192.168.0.62:8000/zl-worklog.html
```

- 端口被占用就换一个（命令里的 `8000` 与访问地址里的端口同步改）；按 **Ctrl+C** 停止服务。
- 首次运行 Windows 防火墙可能弹窗，勾选「专用网络」并允许访问，否则手机连不上。
- 登录态按域名隔离：此地址与 `file://`、Pages 三者**互不相通**，首次打开需重新登录一次，属正常现象。
- 手机连不上时先确认在同一 WiFi、PC 防火墙已放行；页面停在「网络连接失败」则查手机能否访问外网及后端白名单。

**前提：后端允许跨域。** 该 API 的 `OPTIONS` 预检实测返回 `204` 且带 `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Headers: authorization,content-type`，因此 `file://`（`Origin: null`）、Pages 域名（`https://fyw2421.github.io`）以及局域网地址（`http://192.168.x.x:8000`）都能直连。如果后端后续收紧 CORS，页面会停在「网络连接失败」，需同步调整白名单。

## 发布与部署（GitHub Pages）

- 部署方式：**GitHub Actions**（`.github/workflows/pages.yml`），只在 `push main` 或手动触发时运行；
- 产物：workflow 把 `zl-worklog.html` 复制成 `_site/index.html` 上传，并把 head 里的 `<meta name="build" content="local">` 换成本次提交短 SHA；`reference/`、`scripts/`、文档都不会被发布；
- 流水线自检：所有 action 钉到 commit SHA（防上游改行为）、`actionlint` 检查 workflow 本身、部署后用冒烟校验拉线上页面比对 `build` 标记（防止「部署显示成功、站点仍是旧包」的假绿）；
- 部署红了用 `scripts/deploy-retry.ps1` 重跑（`-List 5` 看最近几次、`-Latest` 重跑最新一次，需要 `GITHUB_TOKEN`），不要往 `main` 推空提交；
- 访问地址：`https://fyw2421.github.io/zl-cms-h5/`（根路径即页面，无需带文件名）；
- 前提：仓库 Settings → Pages → **Source 必须选 `GitHub Actions`**（不是 Deploy from a branch），否则部署步骤会因「Pages 站点未启用」失败。

## 接口契约

本页所有请求路径、参数、请求体字段与返回值含义，均与 PC 端一致，**不做二次定义**。

契约一律以 `reference/` 下的两个 PC 端源文件为准，现场检索获取即可；本文档不复述字段清单，避免接口调整后文档变成过期副本：

- `reference/bundle.js`：搜 `"/Worklog/` 可一次列出全部日志接口（`reference/worklog_component.js` 里没有任何接口路径，不要在那里找）；搜 `baseURL` 取基址与 axios 配置；**不要**用 `sft(` / `lft(` 这类压缩后的函数名当锚点，它们每次构建都会变。
- `reference/worklog_component.js`：未压缩、可读，用来核对字段名与表单规则（工时、状态、时间段、部门提交标记），不含路径。

判断本页实际在调哪些接口，直接看 `zl-worklog.html` 里的 `api('get' | 'post', …)` 调用点，这是唯一权威来源。

## 业务规则

- 工作状态：正常上班、全天请假、上午请假、下午请假四种，切换时自动调整时间段与文案；
- 时间段必须是 **5 分钟倍数**，开始早于结束，且互不交叉重复；
- 原生时间选择器（`step=300`）本身只能选 5 分钟倍数；手动键入或粘贴非整 5 分钟的值（如 `09:07`）时，页面**就近取整到 5 分钟**（`09:05`）并 toast 说明「已按 5 分钟调整为 09:05」，不静默改值；
- 工时由时间段自动累加（保留 1 位小数），不手工填写；
- 正常上班且工时为 0 时，弹二次确认（红色「仍要提交」），避免误提交空工时；
- **服务端规则（已实测）**：状态为「正常上班」时，工作日提交的工时不得少于 7 小时（服务端按时间段重算，不信客户端传的 `workHours`；6.9 小时被拒、7 小时整通过），否则返回 `正常工作日您选择的时间段小于7小时`；同样的时间段把状态改为请假类即可通过；
- **服务端规则（已实测）**：当天日志的结束时间不能晚于当前时间，否则返回 `工作时间段结束时间 ... 不能超过当前时间 ...`；页面对此在提交前校验；
- 请假类状态会自动带出默认时间段与文案，切回「正常上班」时恢复默认时段。

## 登录态与有效期

- 本地存储键：`lw_h5_auth_v1`（凭证）、`lw_h5_last_seen_v1`（最后使用时间）、`lw_h5_draft_<userId>|<日期>|<提交部门>`（未提交草稿，见下节）；
- token 的真实有效期**由服务端决定**，客户端拿不到（登录响应不含任何时效字段，PC 端也不记录）。页面按 PC 端同一判定处理身份失效信号；
- 失效与无权限分开处理：身份失效 → 清除凭证、回登录页；无权限 → 只提示，不动登录态；
- 额外兜底：**连续 3 天未使用即作废**。启动时或任一请求前判定，超期直接清除凭证并提示重新登录；每次使用会刷新时间戳（5 分钟内最多写一次，减少存储写入）；
- 手动「退出登录」会一并清除凭证与时间戳，但**不清除未提交草稿**（见下节）。

## 缓存与断网

页面不是离线应用，缓存只覆盖**读取侧**，写日志/提交始终需要联网：

- 缓存键前缀 `lw_h5_cache_`，按「日期 + 部门」缓存日志数据，存于当前页面的 localStorage；
- 请求失败时回落到缓存并显著提示「可能不是最新」；「我的日志」未成功读取时**禁用提交按钮**，避免把已存在的当天日志覆盖成空表单；
- 绑定部门的账号下，「我的日志」与部门日志是同一次请求，页面只请求一次并写两个键，不再重复拉取；
- 写日志页那枚「部门日志已提交 / 未提交」取自这次请求返回行上的 `isDeptSubmit`（任一行 =1 即已提交），**不额外调 `ConfirmDeptWorklogSubmit`**；它只是那一刻的快照，切日期或刷新会重新取。部门日志提交后**不允许撤销**，所以当天这个状态是终态，不需要也不应该在本地下结论；
- 缓存与草稿都按日期入键，**保留最近 7 天，并受 2MB 体积预算约束**：进页面只回收超期键，超预算时从最旧日期开始淘汰缓存（预算内不动，断网回退要用），草稿不计入预算也不被淘汰；本地空间写满时依次「回收过期键 → 让近期缓存让位」，仍失败才提示「本机存储已满」，不让草稿和登录态静默丢失；
- 离线文件与 Pages 是两套存储域，缓存不互通。

## 未提交草稿

写日志表单的改动会在本机自动保存，不动接口，也不上传：

- 键：`lw_h5_draft_<userId>|<日期>|<提交部门>`，按用户 / 日期 / 提交部门三维隔离；
- 写入：内容、状态、时间段变化后 400ms 防抖落盘；页面切后台或刷新（`pagehide` / `visibilitychange`）时同步落盘，所以输入后**立刻刷新也不丢**；
- 切日期、提交部门、查看部门之前先按旧维度落盘，避免 400ms 内的编辑既没进旧键、也没进新键；
- 恢复：**当天没有线上记录**时，草稿与服务端（即初始表单）有差异就自动恢复 —— 第一次写日志写到一半刷新不该丢；**当天已有线上记录**（提交过）时**不再自动恢复**，表单一律回到线上内容，未提交的改动挂成表单顶部的提示条「检测到 MM-DD HH:MM 保存的草稿 ｜ 取回草稿 ｜ 丢弃」，由用户决定去留。刷新/切后台命中的是本机旧副本的问题就此消失，胶囊也只在当前会话表达「改动未保存，提交后才会更新线上」；未读到服务端记录前胶囊与提示条都隐藏、提交按钮置灰，「加载中」不会被说成「未提交」；
- 脏判据：内容 / 工作状态 / 时间段任一异于服务端记录（无记录则异于初始态）。因此只改状态（如请假、内容为空）也会保住；内容清空且其余未改则删除草稿，刷新后不会复活已放弃的内容；
- 清除：仅当表单与服务端一致（含提交成功后、点「丢弃」后）才清该维度草稿；**退出登录不清草稿**（登回自己的号可继续填），下次登录成功会清理旧版无 userId 的孤立草稿键。

## 部门日志已提交后的只读态

提交部门当日已提交部门日志（`isDeptSubmit=1`）后，当天这条个人日志就定了，本机不再允许改：

- 只读范围：工作状态四段按钮、工作内容（`readOnly`，仍可选中复制）、工作时间段（原生 `time` 输入换成同尺寸文本块，不能点开选择器）、新增/删除时间段、全屏编辑、提交按钮；
- 提交按钮在锁定态不再是行动词，改写成「日志已锁定」（灰底 + `not-allowed`），因为此状态下什么都提交不了，写「提交日志 / 更新日志」会承诺做不到的事；
- 点任何一处都弹屏幕正中的提示「部门日志已提交，本日日志已锁定，不能再修改」（居中版 toast 用 `width:max-content`，否则 `left:50%` 的 shrink-to-fit 只给一半宽度，中文会折在「本日日 / 志已锁定」这种位置），表单底部常驻一行同文案的红字说明；部门日志提交后不可撤销，所以这里不给「先去撤销」这类走不通的指路；
- **不用 `disabled`**：`disabled` 的控件收不到点击事件，就没法给出提示，所以一律用「看起来禁用、仍可点」的做法（浅色 + `cursor:not-allowed`）；
- 只读期间不挂「取回草稿」提示条（草稿没有去处），旧草稿留在本机不清，等解除锁定后再说；`flushDraft` 也跳过，避免把草稿顺手删掉；
- 状态来源同上一节：`GetWorklogs` 返回行上的 `isDeptSubmit`，切日期/刷新重读；该状态当天不会回退（不可撤销）。

## 已知限制

- **未实现**：撤销部门日志、按姓名筛选；
- 部门日志截图预览/转发/下载已实现：提交成功自动预览，已提交状态可随时打开；点图片或左上「预览」进入全屏灯箱放大（手机双指捏合/拖拽，桌面滚轮），点遮罩或 ✕ 退出；左钮按环境两档——**移动端（安卓 / iOS / 鸿蒙）只给「转发」（浏览器真支持文件分享时）或直接隐藏、只留「下载截图」**，复制到剪贴板在微信移动端贴不出来，不给假入口；**桌面端才显示「复制截图」**；夸克/UC/QQ 浏览器这类把 `navigator.share` 做成空壳（`canShare` 报 true 但点了不弹面板）的，一律降级为下载，其他浏览器另有 2.5 秒无响应兜底提示；移动端截图弹窗底部常驻一行提示「预览时，长按图片可尝试分享，不成功请用「下载截图」」——长按菜单是浏览器原生 UI，网页探测不到，所以只写「可尝试」并给下载兜底；
- 登录接口的 4 位图形验证码字段在 PC 端也只做前端展示、不随请求发送，本页同样未做；
- 新增时间段与现有时间段冲突时只提示、不阻塞（与 PC 端行为保持一致）；
- 页面不发起任何后台轮询，数据仅在进入页面、切换日期/部门、提交后刷新。
- 单次读取的 `pageSize` 与 PC 端一致（1 万条）：「全部部门」视图下超过 1 万行仍会截断，统计卡与截图同步少人；
- 任一请求 60 秒无响应按超时处理（对齐 PC 端 axios `timeout: 6e4`），按钮会复位并提示重试；部门列表读取失败会在页面顶部显著提示（未绑定部门的账号此时无法提交）。

## 维护提示

- 单文件自包含：CSS 在 `<style>`、JS 在 `<script>`，不拆 js/css 文件；改动后直接覆盖原文件即可；
- 改接口前先回到 `reference/bundle.js` 核对（搜 `"/Worklog/` 与 `baseURL`），字段名再到 `reference/worklog_component.js` 交叉印证，不要照本文档硬拼；
- 回归验证方式：先 `node --check` 校验脚本语法，再用无头浏览器渲染关键状态（登录校验提示、已加载可提交、未加载禁用、状态胶囊三态、零工时确认、部门日志三态）比对截图；草稿相关改动另需覆盖四个场景：清空内容后刷新不复活、只改状态（请假且内容为空）不丢、换账号不串、切日期/部门前落盘；
- 修订前把当前版本复制进 `_backup/`（不存在就先建目录），保留可回退的上一版。

## 安全提示

- 凭证存在页面自己的 localStorage：`file://`、`fyw2421.github.io`、局域网 `http://192.168.x.x:8000` 三个域**互不相通**，走哪种方式都得各自登录一次。页面已用「3 天闲置自动清除 + 服务端 `-2` 双判定」压缩暴露窗口；如对安全要求更高，可改为 `sessionStorage`（代价是每次打开都要重新登录）；
- 草稿同样存在 localStorage，按域隔离之外再按用户 ID 隔离：同机换账号不会串看草稿，也不会把前一个人的内容以后一个人的名义提交（旧版无 userId 的草稿会在下次登录时清理）；
- 本页只读取与提交工作日志，不涉及其他 CMS 模块；请勿把带真实 token 的浏览器数据导出分享；
- 走 GitHub Pages 时页面本身公网可访问，但**没有任何人能在未登录的情况下读写数据**——接口鉴权在服务端。真正需要留意的暴露是接口地址公开，以及仓库若为 public，源码同样公开。
